# ISO/IEC 27001

## Overview

ISO/IEC 27001 is an internationally recognised standard for establishing, implementing, maintaining and continually improving an Information Security Management System (ISMS).

The standard provides a structured approach to managing information security risk across people, processes and technology.

---

## What is an ISMS?

An Information Security Management System provides the governance structure through which an organisation manages information security.

It brings together:

- Information security policies
- Risk management
- Security controls
- Roles and responsibilities
- Security objectives
- Assurance activities
- Continual improvement

The ISMS should be integrated into the organisation's broader risk and governance framework rather than operating as a standalone IT initiative.

---

## Core Implementation Lifecycle

A practical ISO 27001 implementation can be viewed as a continuous cycle:

**Understand → Assess → Plan → Implement → Measure → Improve**

### 1. Understand

Establish organisational context, interested parties, scope and business requirements.

### 2. Assess

Identify information security risks and determine appropriate treatment strategies.

### 3. Plan

Define security objectives, controls, responsibilities and implementation priorities.

### 4. Implement

Implement policies, processes, technical controls and supporting capabilities.

### 5. Measure

Monitor control effectiveness, conduct audits and assess performance against objectives.

### 6. Improve

Address findings, implement corrective actions and continuously improve the ISMS.

---

## Key Governance Components

An effective ISMS should establish clear ownership for:

| Area | Example Responsibility |
|---|---|
| Information Security Strategy | Define security objectives and direction |
| Risk Management | Identify and manage information security risks |
| Policies | Establish organisational expectations |
| Asset Management | Maintain visibility of information assets |
| Access Management | Control access to systems and information |
| Supplier Security | Manage third-party information security risk |
| Incident Management | Respond to and learn from security incidents |
| Business Continuity | Maintain resilience and recovery capability |
| Security Awareness | Develop security culture and capability |
| Assurance | Validate that controls operate effectively |

---

## Statement of Applicability

The Statement of Applicability (SoA) documents the security controls selected by an organisation and provides the rationale for their inclusion, exclusion or implementation status.

The SoA should be treated as a living governance document and reviewed as organisational risks, technology and business requirements change.

---

## Certification vs Security Improvement

ISO 27001 certification can provide valuable independent assurance, but certification should not be the primary objective of an information security program.

The ultimate objective should be:

> **Effective management of information security risk and protection of critical information and business processes.**

Certification should support that objective rather than replace it.

---

## Executive Perspective

From a technology leadership perspective, ISO 27001 provides a useful governance framework for connecting:

**Business Strategy → Risk → Security Controls → Assurance → Continuous Improvement**

A successful ISMS requires engagement across the organisation and should ultimately be owned as a business risk and governance capability, not simply as an IT responsibility.
